# 3D リデザイン・UI/UX 改善・ポップ BGM 実装ログ

**Date:** 2026-10-14
**Branch:** `claude/3d-redesign-bgm`
**Request:** 3D を取り入れたリデザイン、UI/UX の改善、軽快なポップ BGM を複数から選択可能に。

## 背景（着手時の状態）

- 実際にブラウザで動いていたのは正規表現ベースの変換スクリプト（`build.js` ほか）で生成された `src/**/*.js` で、`.ts` と内容が乖離していた（ローカライズ・アドバイスは JS のみに存在）。
- Vitest は `.ts` より `.js` を優先解決していたため、テストは古い JS を対象に走り多数失敗していた。
- `.eslintrc.json` の `extends` 指定が誤っており lint は機能していなかった。
- 操作は `prompt()` / `confirm()` 依存、スタッフ雇用と設備強化は no-op、一時停止は未実装、ゲームは実質 8 日間続くバグがあった。

## 実施内容

### ビルド基盤
- Vite 7 + TypeScript 5.9（strict）に移行し、TS を唯一のソースに。生成 JS・変換スクリプト・重複ディレクトリ・`opening.html`・`test-game.html` を削除。
- ESLint 9（flat config, typescript-eslint）、Prettier、Vitest 5、Playwright 1.56 を整備。
- CSP を `script-src 'self'` に強化（`'unsafe-inline'` を除去）。フォント（M PLUS Rounded 1c）と three.js はローカルにバンドル。

### ゲームモデル
- `GameEngine` を DOM 非依存に再設計（1 秒固定 tick、イベント通知、スナップショット保存/復元）。
- 経済モデルを `Simulation.ts` の純粋関数に分離：需要曲線（ランチ/ディナーのピーク）、魅力度（価格・満足度・話題度・品揃え・人気）、処理能力（スタッフ×厨房 Lv×調理時間）、満足度・人気の目標値。
- 雇用・厨房強化・キャンペーン（SNS/ラジオ/TV）を実装し、全アクションに失敗理由（ローカライズキー）を返すように。
- 7 日目終了で正確に終わるよう修正。イベントの持続時間を実時間 `setTimeout` からシミュレーション時間に変更（一時停止中に進まない）。
- AI 5 戦略を見直し（StrategicAI が原価割れ価格を付けるバグを修正、各 AI が同じ検証経路で行動）。

### 3D（three.js）
- 桜の木を中心に 6 店舗が並ぶローポリの広場。店ごとのブランドカラー、看板（Canvas テクスチャ、言語切替に追従）、シェア柱、首位の王冠、プレイヤー店マーカー。
- 1 日の進行に合わせた空・太陽・街灯/窓の発光、天気（雲・雨）、花びら、来客の群衆（InstancedMesh + 純粋ロジックの `CrowdSimulator`）、キャンペーン時の紙吹雪。
- UI パネルに隠れない位置にカメラをフレーミング（`setViewOffset`）。ドラッグで回転、店舗クリックでライバル偵察。
- WebGL 非対応環境では 2D UI のみで継続プレイ可能。省電力モード / reduced-motion 対応。

### BGM・効果音
- Web Audio によるリアルタイム合成（音源ファイル不要・ライセンス問題なし）。オリジナル 4 曲：さくらポップ（王道進行）/ キッチンバウンス（ファンク・スウィング）/ ネオンダイナー（シンセポップ）/ ランチラッシュ（チップチューン）。
- 先読みスケジューラ、リード/ベース/コード（スタブ・アルペジオ）/ドラム合成、エコー。曲切替はクロスフェード。
- タイトル画面と一時停止メニューから選択・試聴、音量・ミュート設定は保存。

### UI/UX
- タイトル画面（店名・難易度・BGM・言語・つづきから）。
- HUD（日数ピップ、時間帯とピーク表示、変化時にフラッシュする指標）、ライブランキング（並べ替えアニメーション）、売上推移チャート、サクラの助言フィード（「開く」で該当タブへ）、市場イベントのタイマー表示、ライバル情報カード。
- 操作ドック：価格ステッパー、料理追加ダイアログ（プリセット・利益率プレビュー・インライン検証）、削除の取り消し、購入不可時の無効化、混雑率メーター。
- 一時停止兼設定メニュー、キーボードショートカット、トースト通知、結果画面（表彰台・各賞）。
- アクセシビリティ：フォーカストラップ付きダイアログ、ARIA ロール/ラベル、`prefers-reduced-motion`。スマホ幅ではスクロールレイアウト。

## 得られた知見

- **バランス調整**：ヘッドレスで 1 ゲーム丸ごと回すシミュレーションで調整。初期値では全店が赤字・処理能力が律速にならない・高価格戦略が成立しない状態だった。需要/客単価/処理能力/満足度の重み付けを調整し、「能動的なプレイヤーは Easy で必ず勝ち、Normal で 2 位前後、Hard ではさらに厳しい」曲線にした。シード固定の回帰テスト（`src/game/Balance.test.ts`）として残した。
- **カメラのフレーミング**：全画面の 3D に UI を重ねると自店がドックに隠れる。グリッドの空き領域（`#stage`）を計測して `setViewOffset` で中心をずらす方式にした（`docs/ARCHITECTURE.md`）。
- **助言の重複**：同カテゴリの連続表示は冷却時間を 3 倍にし、文言はバリエーションを順番に回すようにした。
- **jsdom の制約**：canvas 2D は setup でフェイク化、WebGL 部分は `SceneRenderer.ts` に閉じ込めて単体カバレッジ対象外とし、Playwright で担保。

## 制約・既知の事項

- `SceneRenderer.ts` と `main.ts` は単体テストのカバレッジ対象外（E2E で担保）。
- three.js により JS バンドルは約 550 KB（gzip 約 137 KB）。別チャンクに分割済み。
- 日本語フォントは unicode-range 分割で必要なグリフのみ取得されるが、CSS は約 310 KB（gzip 約 130 KB、太字は 800 ウェイトに統一して削減）。
- CLAUDE.md の「Libraries: Canvas API, Chart.js, DOM manipulation only」に対し、3D 要件のため three.js を追加（チャートは Chart.js を使わず Canvas で自作）。
